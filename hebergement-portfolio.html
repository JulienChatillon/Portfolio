Contexte et objectifs

Pour présenter mes réalisations de BTS SIO, je me suis donné un projet de bout en bout : créer mon portfolio, puis l’héberger moi-même. Je n’ai pas de compétence en développement : la première version du site a été générée avec Antigravity (elle n’existe plus), puis tout le site actuel a été réalisé avec Claude, que j’ai dirigé sur la forme et le contenu, puis relu et testé. Plutôt que de passer par un hébergeur, je l’ai installé sur mon propre réseau, dans une zone démilitarisée (DMZ) du pare-feu, derrière un reverse proxy qui gère le certificat HTTPS. Le site était prêt en janvier 2026 ; le nom de domaine, pris chez Infomaniak, l’a rendu public en février.

Objectifs

  1. 1

    Concevoir et construire le site avec des outils d’intelligence artificielle (Antigravity, puis Claude), en gardant la maîtrise du résultat.

  2. 2

    Auto-héberger le site (conteneur Nginx) sur mon infrastructure Proxmox.

  3. 3

    Isoler le site dans une zone démilitarisée (DMZ) du pare-feu pfSense, séparée de mon réseau interne.

  4. 4

    Centraliser les accès web avec un reverse proxy (Nginx Proxy Manager) et sécuriser les échanges par un certificat HTTPS.

  5. 5

    Rendre le site joignable sous mon nom de domaine, en n’exposant que les ports web 80 et 443.

Mise en œuvre

1

Concevoir le site avec l’IA

Une première version avec Antigravity, aujourd’hui supprimée. Le site actuel est construit avec Claude : gabarits des pages, schémas animés, en-têtes de sécurité. Je décide de la forme, je relis, je teste et je déploie.

2

Préparer la DMZ

Une zone réseau dédiée (10.10.19.0/24) sur pfSense héberge la machine virtuelle Debian du service. Elle est séparée du réseau interne.

3

Installer Nginx Proxy Manager

Nginx Proxy Manager tourne dans Docker sur cette machine. C’est le point d’entrée unique du trafic web : il gère le certificat et transmet le domaine au conteneur du site. Son interface d’administration n’est accessible que depuis le réseau interne, avec un certificat interne.

4

Servir le site

Le site statique est servi par un conteneur Nginx (port 8080) dont la configuration ajoute les en-têtes de sécurité, avec les fichiers du site montés depuis la machine.

5

Ouvrir le passage depuis Internet

Sur la box, les ports 80 et 443 sont redirigés vers pfSense. Sur pfSense, une règle de traduction d’adresses (NAT) les envoie vers le reverse proxy de la DMZ.

6

Réserver le nom de domaine

Le domaine julien-chatillon.com, pris chez Infomaniak, pointe vers l’adresse publique de la box, qui est fixe.

7

Activer HTTPS

Dans Nginx Proxy Manager, un certificat Let’s Encrypt est demandé pour le domaine, avec redirection forcée vers HTTPS.

8

Mettre à jour et documenter

Je déploie par copie sur la machine, puis je sauvegarde sur GitHub (dépôt privé, avec une version publique dont les adresses et les ports sont masqués). Les journaux d’accès sont purgés à 30 jours, comme l’annoncent les mentions légales.

Difficultés rencontrées

Problème

Dans nginx, des en-têtes de sécurité déclarés dans un bloc « location » annulent ceux du serveur pour les fichiers concernés.

Solution

J’ai placé tous les en-têtes au niveau du serveur, et vérifié le résultat avec securityheaders.com.

Problème

La politique de sécurité du contenu interdit les scripts écrits dans les pages.

Solution

Tous les scripts sont dans des fichiers séparés ; la console du navigateur reste sans erreur.

Bilan

Ce projet m’a fait passer de l’idée au service en ligne : un site que je ne sais pas coder, construit avec des outils d’IA, puis un hébergement que je maîtrise de la box au certificat. J’ai surtout appris à penser l’exposition d’un service : un point d’entrée unique, une zone séparée du réseau interne, un certificat qui se renouvelle et des en-têtes de sécurité que je peux mesurer.

Les limites sont claires : le site est statique, sans analyse d’audience (les scripts extérieurs sont interdits), et c’est moi qui le mets à jour à la main.

Pour aller plus loin

  • Documenter dans une fiche les règles de la DMZ et les tester à chaque changement.
  • Déclarer le plan du site à un outil comme Google Search Console pour suivre l’indexation.
  • Sauvegarder le site hors de l’infrastructure.
